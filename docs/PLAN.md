# แผนพัฒนาเว็บฐานข้อมูล MONGIL: STAR DIVE (ภาษาไทย)

> เอกสารนี้คือแผนตั้งต้นของ repo `mongil-star-dive-tools` — เว็บรวมข้อมูลตัวละคร, Artifact,
> Monsterling, อาหาร และ Build guide สำหรับเกม MONGIL: STAR DIVE

## 1. เป้าหมาย

เว็บ static ที่โหลดเร็ว ค้นหา/กรองข้อมูลได้ไว เปิดบนมือถือสวย และ **แก้ข้อมูลได้โดยไม่ต้องแตะโค้ด**
(แก้ไฟล์ JSON ไฟล์เดียวต่อ 1 รายการ แล้ว push → เว็บอัปเดตอัตโนมัติ)

กลุ่มผู้ใช้หลัก: ผู้เล่นไทยที่อยากรู้ว่า "ตัวนี้ Awaken ถึงขั้นไหนคุ้ม", "ควรใส่ Artifact อะไร",
"Monsterling ตัวไหนเข้ากับสายนี้", "ก่อนตีบอสควรกินอะไร"

### ขอบเขตที่ตกลงแล้ว

| หัวข้อ | ที่เลือก |
|---|---|
| Stack | Next.js (App Router) + TypeScript + Tailwind CSS |
| ภาษา | ไทย + อังกฤษ (i18n ตั้งแต่แรก, ไทยเป็น default) |
| ที่มาข้อมูล | กรอกเอง + แคปหน้าจอจากเกม |
| Hosting | Vercel (หรือ GitHub Pages ถ้าอยากฟรี 100% — รองรับทั้งคู่ด้วย static export) |

## 2. ระบบในเกมที่ต้องสะท้อนในข้อมูล

สรุปจากการสำรวจข้อมูลเกม (ต้องยืนยันตัวเลขจริงในเกมอีกที ก่อนเผยแพร่):

- **Awaken** — ทำได้สูงสุด 6 ขั้น (ได้จากการปั้มตัวซ้ำ) ขั้นที่ **3** และ **5** ให้ +2 เลเวลสกิล
  ทำให้สกิลทะลุเพดานปกติ 12 ไปถึง **16** ได้
- **Skill** — มี 4 ประเภท: Basic Attack, Switch Skill, Special Skill, Ultimate Skill
  อัปได้ถึง 12 ต่อสกิล (ทะลุถึง 16 ด้วยโบนัส Awaken ข้างบน)
- **Artifact** — เป็นอาวุธ มีค่าสเตตัสตายตัว + เอฟเฟกต์ประจำชิ้น
- **Monsterling** — ได้จากการ Capture มอนสเตอร์ หรือ Combine ให้สเตตัสพื้นฐาน + ความสามารถ
  ตามสายพันธุ์ (breed) และ Trait
- **Cooking** — ปลดล็อกจากเควสรอง "Healthy Meals" ใน Episode 1 แบ่งเป็น **Entree** กับ **Side**
  ใส่พร้อมกันได้ทั้งสองอย่าง บัฟอยู่ราว 30 นาที มีโอกาสออกเวอร์ชัน **Exquisite** ที่ค่าสูงกว่า
  วัตถุดิบบางช่องสลับได้ (มีไอคอนเปลี่ยนมุมขวาบน) สูตรบางส่วนซื้อจาก Brownie ที่ Hananis

> ⚠️ ทุกตัวเลขในเว็บต้องมีฟิลด์ `verifiedAt` (เวอร์ชันเกม + วันที่ยืนยัน) เพราะเกมแนวนี้ปรับบาลานซ์บ่อย

│  ├─ process-images.ts           ← crop + resize + แปลง webp/avif ด้วย sharp
│  ├─ validate-data.ts            ← ตรวจ schema + cross-reference + รูปครบไหม
│  └─ new-entry.ts                ← สร้างไฟล์ JSON เปล่าจาก template
├─ src/
│  ├─ app/[locale]/...            ← หน้าเว็บ
│  ├─ components/                 ← การ์ด, ตาราง, ตัวกรอง, skill accordion ฯลฯ

**ทำไมแยกไฟล์ละรายการ:** diff อ่านง่าย, แก้พร้อมกันหลายตัวไม่ conflict, และ copy template ใหม่ได้ไว

## 4. Data model

ทุก entity ใช้ `id` (slug ภาษาอังกฤษ ตัวพิมพ์เล็ก-ขีดกลาง) เป็น primary key และอ้างอิงกันด้วย id
ฟิลด์ข้อความที่ผู้ใช้เห็นเป็น `{ "th": "...", "en": "..." }` เสมอ

### 4.1 Character — `data/characters/jiwon.json`

```jsonc
{
  "id": "jiwon",
  "name": { "th": "จีวอน", "en": "Jiwon" },
  "rarity": 5,                    // จำนวนดาว เกมมีแค่ 4 กับ 5
  "element": "fire",              // อ้าง meta/elements.json
  "role": "supporter",            // fighter | destroyer | assassin | supporter
  "releaseVersion": "1.0",
  "stats": {                      // ค่าเปล่าตอนถอดอุปกรณ์หมด + ระบุว่าวัดที่เลเวลไหน
    "atLevel": 60,
    "hp": 12345, "atk": 1234, "def": 567, "critRate": 5, "critDmg": 50
  },
  "skills": {
    "basic":    { "name": {...}, "desc": {...}, "scaling": ["120%", "...16 ค่า"], "tags": ["aoe"] },
    "switch":   { "name": {...}, "desc": {...}, "cooldown": 12, "scaling": [...] },
    "special":  { "name": {...}, "desc": {...}, "cooldown": 20, "scaling": [...] },
    "ultimate": { "name": {...}, "desc": {...}, "cost": 100, "scaling": [...] }
  },
  "awaken": [                     // ปลุกพลังด้วยตัวซ้ำ 6 ขั้น เรียงจาก 1 → 6
    { "stage": 1, "name": {...}, "desc": {...}, "type": "stat" },
    { "stage": 3, "name": {...}, "desc": {...}, "type": "skillLevel", "skillLevelBonus": 2 },
    { "stage": 5, "name": {...}, "desc": {...}, "type": "skillLevel", "skillLevelBonus": 2 }
  ],
  "awakenPriority": { "recommended": 3, "note": { "th": "คุ้มสุดที่ A3 ...", "en": "..." } },
  "recommended": {                // ทั้งหมดเป็น id ที่ต้องมีอยู่จริง → validate ตอน build
    "artifacts": ["blazing-edge"], "monsterlings": ["flare-pup"], "food": ["spicy-stew"],
    "teammates": ["ariel"], "builds": ["jiwon-boss-dps"]
  },
  "images": { "icon": "jiwon-icon.webp", "portrait": "jiwon-portrait.webp", "splash": "jiwon-splash.webp" },
  "source": { "verifiedAt": "2026-09-11", "gameVersion": "1.4.0", "by": "in-game screenshot" }
}
```

### 4.2 Artifact
`id, name, rarity, type, mainStat, subStats[], effect{name,desc}, refineLevels[], recommendedFor[characterId], obtainFrom, images.icon, source`

### 4.3 Monsterling
`id, name, breed, rarity, traits[], baseStats{}, ability{name,desc}, obtain{ method: "capture"|"combine", location, combineRecipe[monsterlingId] }, goodWith[characterId], images.icon, source`

### 4.4 Food
`id, name, category: "entree"|"side", buff{ stat, value, isPercent }, durationMinutes: 30,
exquisite{ buff }, ingredients[{ itemId, qty, swappable: bool }], unlock{ from: "brownie-shop"|"event"|"quest" }, images.icon, source`

### 4.5 Build
`id, characterId, title{}, contentType: "boss"|"pvp"|"story"|"farming", author, updatedAt,
artifacts[], monsterlings[], food{entree, side}, skillPriority[], awakenTarget,
teamComps[{name, members[characterId], note}], pros[], cons[], notes{}`

### 4.6 การบังคับความถูกต้อง

- **zod schema** ต่อทุก entity ใน `src/lib/schema/`
- `scripts/validate-data.ts` รันใน CI + pre-commit hook: เช็ค schema ผ่าน, ทุก id ที่อ้างถึงมีอยู่จริง,
  ไฟล์รูปทุกไฟล์ที่ระบุมีจริงใน `public/images/`, ไม่มี id ซ้ำ
- build จะ **fail** ถ้าข้อมูลพัง — กันข้อมูลผิดหลุดขึ้นเว็บ

## 5. หน้าเว็บ

| Route | เนื้อหา |
|---|---|
| `/` | หน้าแรก: ช่องค้นหารวม, ทางลัดไป 5 หมวด, ตัวละครอัปเดตล่าสุด, build ใหม่ |
| `/characters` | ตาราง/กริดการ์ด + กรองตาม element, role, rarity + เรียง + ค้นหาชื่อไทย/อังกฤษ |
| `/characters/[slug]` | **หน้าหลักของโปรเจกต์** (ดูรายละเอียดข้างล่าง) |
| `/artifacts` · `/artifacts/[slug]` | ลิสต์ + กรองตาม rarity/main stat · หน้ารายละเอียด + ใครควรใส่ |
| `/monsterlings` · `/monsterlings/[slug]` | ลิสต์ + กรอง breed/trait · รายละเอียด + สูตร Combine (แสดงเป็นแผนผัง) |
| `/food` · `/food/[slug]` | แยกแท็บ Entree / Side, กรองตามบัฟ · รายละเอียด + วัตถุดิบ + ช่องที่สลับได้ |
| `/builds` · `/builds/[slug]` | กรองตามตัวละคร/ประเภทคอนเทนต์ · หน้า build เต็ม |
| `/about` | ที่มาข้อมูล, เวอร์ชันเกมที่อ้างอิง, ข้อความ disclaimer ลิขสิทธิ์, วิธีส่งข้อมูลแก้ไข |

### หน้าตัวละคร `/characters/[slug]` — โครงหน้า

1. **Hero** — splash art + ชื่อไทย/อังกฤษ + ป้าย rarity/element/role
2. **Stats** — ตารางค่าสเตตัส ระบุชัดว่าวัดที่เลเวล/BT เท่าไร
3. **Skills** — 4 แท็บ (Basic / Switch / Special / Ultimate)
   แต่ละอันมี **สไลเดอร์เลเวล 1–16** เลื่อนแล้วตัวเลขในคำอธิบายเปลี่ยนตาม
   ช่วง 13–16 ขึ้นป้าย "ต้อง Awaken 3 / 5"
4. **ปลุกพลัง (Awaken)** — ไทม์ไลน์ 6 ขั้นจากตัวซ้ำ ไฮไลต์ขั้น 3 กับ 5 (+2 skill level) + คำแนะนำว่าหยุดที่ขั้นไหนคุ้ม
5. **Recommended** — การ์ด Artifact / Monsterling / อาหาร / เพื่อนร่วมทีม (คลิกข้ามหน้าได้)
6. **Builds** — ลิสต์ build ของตัวนี้
7. **Footer** — `verifiedAt` + เวอร์ชันเกม

### ฟีเจอร์ที่ใช้ร่วมกันทุกหน้า

- ค้นหาแบบ fuzzy (Fuse.js) บน index เล็ก ๆ ที่ generate ตอน build — ไม่ต้องมี backend
- ตัวกรองผูกกับ URL query (`?element=fire&role=dps`) → แชร์ลิงก์ตัวกรองได้
- Dark mode เป็นค่าเริ่มต้น + สลับได้
- Responsive: มือถือเป็น 1 คอลัมน์, การ์ดเป็น list, ตารางสเตตัสมี `overflow-x: auto`

## 6. Pipeline รูปภาพ

```
แคปจากเกม (PNG เต็มจอ)
   └─> assets-src/characters/jiwon-splash.png     (ไม่ commit)
         └─> pnpm images                          (scripts/process-images.ts, ใช้ sharp)
               ├─ crop ตามพิกัดใน assets-src/crop.json (ครอปซ้ำได้เหมือนเดิมทุกครั้ง)
               ├─ resize 3 ขนาด: icon 128px / portrait 512px / splash 1280px
               ├─ export .webp (คุณภาพ 82) + .avif
               └─> public/images/characters/jiwon-{icon,portrait,splash}.webp
```

- ตั้งชื่อไฟล์ตายตัว: `<slug>-<variant>.webp` → เดาชื่อจาก id ได้ ไม่ต้องพิมพ์ path เอง
- ใช้ `next/image` + `placeholder="blur"` (สร้าง blurDataURL ตอน build) กันภาพกระตุก
- `validate-data.ts` เตือนถ้ามีรายการที่ยังไม่มีรูป หรือมีรูปที่ไม่มีรายการอ้างถึง (ไฟล์ขยะ)
- ถ้า repo เริ่มใหญ่เกิน ~500MB ค่อยย้ายไป Git LFS หรือ Cloudflare R2

### ⚠️ เรื่องลิขสิทธิ์ (ต้องทำตั้งแต่วันแรก)

ภาพและชื่อทั้งหมดเป็นของ Netmarble / ผู้พัฒนา — เว็บนี้เป็น fan site ไม่ใช่ของทางการ ดังนั้น:
- ใส่ disclaimer ที่ footer ทุกหน้า + หน้า `/about`
- ห้ามใช้โลโก้เกมเป็นโลโก้เว็บ, ห้ามทำให้เข้าใจผิดว่าเป็นเว็บทางการ
- ถ้าจะขึ้นโฆษณา/หารายได้ ให้อ่านนโยบาย fan content ของผู้พัฒนาก่อน

## 7. สองภาษา (ทำแล้ว)

**แก้จากร่างแรก:** ร่างไว้ว่าจะใช้ `next-intl` — ไม่ได้ใช้ เพราะข้อความของตัวเว็บเอง
(ปุ่ม หัวข้อ ป้ายกำกับ) มีไม่ถึงร้อยบรรทัด ส่วนข้อความที่เยอะจริงคือข้อมูลเกม
ซึ่งอยู่ในไฟล์ `data/` เป็น `{ th, en }` อยู่แล้ว ไม่ได้ผ่านระบบ i18n เลย
เขียนเองประมาณ 60 บรรทัดจึงคุ้มกว่า และเป็น static ล้วน ไม่ต้องมี middleware

### แยกข้อความสองกอง

| กอง | อยู่ที่ | อัปเดตเมื่อไหร่ |
|---|---|---|
| ข้อความของเว็บ (ปุ่ม หัวข้อ) | `src/i18n/th.json` · `en.json` | ตอนแก้ UI |
| ข้อมูลเกม (ชื่อ คำบรรยายสกิล) | `data/**/*.json` เป็น `{ th, en }` | ตอนเกมอัปเดต |
| คำศัพท์ (ธาตุ บทบาท stat) | `data/meta/vocabulary.json` มี `th`/`en` ในตัว | นาน ๆ ครั้ง |

กองที่สามสำคัญ — คำว่า "พลังโจมตี / ATK" ไม่ต้องแปลซ้ำที่ไหนอีกเลย ทั้ง schema
และป้ายบนหน้าเว็บอ่านจากพจนานุกรมไฟล์เดียวกัน

### เส้นทาง

```
/            → 307 ไป /th
/th/...      ภาษาไทย  <html lang="th-TH">
/en/...      อังกฤษ   <html lang="en">
/xx/...      404
```

ทั้ง `/th` และ `/en` ถูก prerender เป็น static ตอน build (`generateStaticParams`)
ปุ่มสลับภาษาเป็น `<a>` ที่ชี้ไปหน้าเดิมอีกภาษา (`/th/characters/nova` → `/en/characters/nova`)
ใช้ลิงก์ไม่ใช่ปุ่ม เพื่อให้คลิกขวาเปิดแท็บใหม่ได้ และ Google ตามลิงก์เจอทั้งสองภาษา

### กฎ fallback

ข้อมูลเกมมาเป็นอังกฤษก่อนเสมอ แล้วค่อยทยอยแปลไทย ระหว่างนั้น:

- `pickText()` คืนข้อความอีกภาษามาแทน **พร้อมธง `isFallback`**
- คอมโพเนนต์ `<Text>` แสดงข้อความนั้นพร้อมป้าย **"ยังไม่แปล"** และใส่ `lang=""`
  ที่ element นั้นให้ตรงภาษาจริง — screen reader จะได้อ่านด้วยสำเนียงถูก
  และเบราว์เซอร์ตัดบรรทัดถูกหลักภาษา (ภาษาไทยไม่มีช่องว่างระหว่างคำ จุดนี้มีผลจริง)
- `validate:data` นับช่องที่ยังไม่มีภาษาไทยเป็น **คำเตือน ไม่ใช่ error** — งานแปลไม่บล็อกการลงข้อมูล

เว็บจึงไม่พังระหว่างทยอยแปล แต่ก็ไม่ทำเป็นว่าข้อความอังกฤษคือฉบับแปลไทย

### SEO

`alternates.languages` สร้าง `<link rel="alternate" hreflang>` ให้ทั้งสองภาษา
บวก `x-default` ชี้ไปไทย และมี `metadataBase` เพื่อให้ URL เป็นแบบเต็ม
(Google ไม่รับ hreflang ที่เป็นพาธสัมพัทธ์) ตั้งโดเมนจริงผ่าน `NEXT_PUBLIC_SITE_URL`

### ยังไม่ได้ทำ

- ยังไม่จำภาษาที่ผู้ใช้เลือก — เข้า `/` ทีไรก็ไป `/th` ตลอด
  (จะใส่คุกกี้หรืออ่าน `Accept-Language` ก็ได้ แต่ทำให้ `/` ไม่เป็น static แล้ว รอดูว่าจำเป็นไหม)
- ยังไม่มี `Intl.PluralRules` — ยังไม่มีข้อความไหนต้องผันพจน์

## 13. ปัญหาที่จะเจอทีหลัง — สิ่งที่ต้องตัดสินใจ**ก่อน**ลงข้อมูลจริง

ทุกข้อในนี้ถ้าตัดสินใจทีหลัง = ต้องไล่แก้ไฟล์ข้อมูลทุกไฟล์ที่กรอกไปแล้ว

### 13.1 id ห้ามเปลี่ยนตลอดชีพ ⚠️ สำคัญที่สุด

`id` คือ URL (`/characters/nova`) ถ้าแก้ id ทีหลัง:

- ลิงก์ที่คนแชร์ไปในกลุ่ม Discord/Facebook **ตายหมด**
- อันดับใน Google รีเซ็ต
- ทุกไฟล์ที่อ้างถึง id นั้นพังพร้อมกัน (validate จะจับได้ แต่ต้องไล่แก้มือ)

**นโยบาย:** id ตั้งครั้งเดียวแล้วห้ามแตะ ถ้าเกมเปลี่ยนชื่อตัวละคร ให้แก้แค่ `name`
และเพิ่มฟิลด์ `aliases: ["ชื่อเก่า"]` เพื่อให้ค้นหาด้วยชื่อเก่ายังเจอ

> ยังไม่ได้ใส่ `aliases` ใน schema — ใส่ตอนไหนก็ได้ แต่ **นโยบายห้ามแก้ id ต้องเริ่มวันนี้**

### 13.2 ค่าสเกลสกิล 16 เลเวล = งานที่จะฆ่าโปรเจกต์

4 สกิล × 16 เลเวล = **64 ตัวเลขต่อตัวละครหนึ่งตัว** ถ้าทำ 15 ตัวคือพิมพ์มือ 960 ตัวเลข
จากหน้าจอเกม ซึ่งต้องกดดูทีละเลเวล งานนี้ใหญ่กว่างานเขียนเว็บทั้งเว็บรวมกัน

schema รองรับ `null` แล้ว (ช่องที่ยังไม่รู้ค่า) แต่ต้องตัดสินใจว่าจะกรอกแค่ไหน:

| ทางเลือก | ต่อตัวละคร | เหมาะกับ |
|---|---|---|
| **กรอกแค่ LV 1 / 12 / 16** ← แนะนำ | 12 ตัวเลข | คนส่วนใหญ่ดูแค่ค่าสุดท้าย |
| กรอกครบ 16 เลเวล | 64 ตัวเลข | คนคำนวณจริงจัง ทำทีหลังได้ |
| ไม่กรอกเลย ใส่แค่คำบรรยาย | 0 | เว็บอ่านอย่างเดียว ไม่มีเครื่องคำนวณ |

เริ่มที่ทางเลือกแรก แล้วเติมทีหลังได้เพราะช่องที่เหลือเป็น `null` อยู่แล้ว

### 13.3 `source.by` ต้องกรอกตั้งแต่แรก

ตอนนี้ `by` เป็น optional — **ควรเปลี่ยนเป็นบังคับก่อนเริ่มกรอกข้อมูลจริง**

เหตุผล: อีกสามเดือนถ้าเจอค่าที่น่าสงสัย จะไม่มีทางรู้ว่าค่านั้นมาจากแคปหน้าจอเอง
หรือลอกมาจากเว็บอื่น (ซึ่งอาจผิดมาตั้งแต่ต้น) ย้อนกลับไปใส่ทีหลังไม่ได้เพราะจำไม่ได้แล้ว

ค่าที่ควรใช้: `"in-game"` · `"official-notice"` · `"community:<ชื่อเว็บ>"`

### 13.4 เกมอัปเดตแล้วค่าเก่าไปไหน

**ไม่ต้องเก็บประวัติในไฟล์ JSON** — git เก็บให้อยู่แล้ว
หน้า changelog สร้างจาก `git log` ของโฟลเดอร์ `data/` ได้ตอนทำ M6
ถ้าเก็บ history ซ้อนใน JSON ไฟล์จะบวมและต้องดูแลสองที่

### 13.5 รูปภาพจะบวมจนโคลน repo ช้า

ตอนนี้ 15 ตัวละคร × 3 ขนาด ยังไม่มีปัญหา แต่ถ้าถึง 100 ตัว + สกิน + ไอคอนของทุกชิ้น
จะแตะหลายร้อย MB และคนโคลนใหม่จะรอนาน

**เกณฑ์:** เมื่อ `public/images/` เกิน **300 MB** ให้ย้ายไป Cloudflare R2 หรือ Git LFS
ยังไม่ต้องทำตอนนี้ แต่ตั้งเกณฑ์ไว้จะได้ไม่ปล่อยจนแก้ยาก

### 13.6 ถ้ามีคนอื่นมาช่วยกรอก

JSON แก้ยากสำหรับคนไม่เขียนโค้ด ทางที่ถูกที่สุดคือ **issue template บน GitHub**
ให้กรอกเป็นฟอร์มแล้วเราแปลงเป็น JSON เอง ยังไม่ต้องทำหน้า admin
(Vercel preview ต่อ PR ที่มีอยู่แล้วช่วยให้รีวิวจากหน้าเว็บจริงได้ก่อน merge)

### 13.7 คำอธิบายท่า (`desc`) — ตัดออกจากขอบเขต

ในจอรายละเอียดลิงก์เชน เหนือหัวข้อ [เงื่อนไขปรากฏตัว] จะมีย่อหน้าบรรยายท่าโจมตี
เช่น "โดยจะกระโดดใส่ศัตรูและฟาดลงหลายครั้ง สร้างดาเมจกายภาพ"

**ตัดสินใจแล้วว่าไม่เก็บ** (2026-09-12) เพราะ:

- เป็นข้อความบรรยายล้วน ไม่มีตัวเลขให้คำนวณ ไม่มีผลต่อการจัดทีมหรือคำนวณดาเมจ
- พาเนลขวาในเกมเลื่อนได้ และตอนเปิดมักไม่ได้อยู่บนสุด ทำให้แคปติดแค่ท้ายประโยค
  ต้องเลื่อนขึ้นก่อนแคปทุกชิ้น — ต้นทุนสูงเทียบกับประโยชน์

ผลที่ตามมา:

- `desc` ยังคงเป็นฟิลด์ optional ใน schema และ**ของที่เก็บไว้แล้ว 24 ระดับยังอยู่**
  (เป็นข้อมูลที่อ่านจากจอจริง ไม่มีเหตุผลต้องลบ)
- จะมีภาษาเดียวหรือไม่มีเลยก็ได้ — `validate:data` ไม่เตือนเรื่อง `desc` อีกต่อไป
- หน้าเว็บต้องแสดงได้ทั้งกรณีมีและไม่มี และกรณีมีแค่ภาษาเดียว
- ตัวเลขความครบถ้วนของลิงก์เชนนับจาก ชื่อ / เงื่อนไข / appearanceInfo /
  bonusEffects เท่านั้น ซึ่ง**ครบ 100% แล้ว**

### 13.8 ป้าย "ใส่ลิงก์เชนได้" — คำนวณเอา ไม่เก็บซ้ำ

ตอนรีวิว mockup เคยขอว่า "บางตัวใส่ link ได้ บางตัวไม่ได้ ให้มีสัญลักษณ์"
**ตัดสินใจแล้วว่าไม่ทำไอคอนของลิงก์เชนเอง** (2026-09-12) ใช้ป้ายแปะบนการ์ดมอนแทน

- ลิงก์เชนทั้ง 64 ใบชี้ไปที่ `monsterlingId` อยู่แล้ว → รู้ได้ทันทีว่ามอนตัวไหนใส่ได้
- จึง**ลบฟิลด์ `monsterling.linkable` ทิ้ง** และลบ `images` ออกจาก `linkChain`
  เพราะถ้าเก็บสองที่ วันหนึ่งจะไม่ตรงกันแล้วไม่มีใครรู้ว่าอันไหนถูก
- โค้ดอยู่ที่ `src/lib/linkable.ts` มี selftest คุม

**ต้องมีสามสถานะ ไม่ใช่สอง:**

| สถานะ | เงื่อนไข | ป้าย |
|---|---|---|
| `yes` | มีลิงก์เชนชี้มา | ใส่ลิงก์เชนได้ |
| `no` | ไม่มีชี้มา **และ**ยืนยันแล้วว่ารายการในเกมครบ | ใส่ลิงก์เชนไม่ได้ |
| `unknown` | ไม่มีชี้มา แต่ยังไม่ยืนยัน | ไม่แปะป้าย |

ตอนนี้ `LINK_CHAIN_LIST_IS_COMPLETE = false` เพราะยังไม่ยืนยันว่าหน้าลิงก์เชนในเกม
แสดงครบทุกใบ หรือแสดงเฉพาะใบที่ผู้เล่นคราฟต์แล้ว **ถ้ายืนยันได้ว่าครบ**
เปลี่ยนค่านี้เป็น `true` ที่เดียว มอนอีก 105 ตัวจะกลายเป็น "ใส่ลิงก์เชนไม่ได้" ทันที

### 13.9 เอฟเฟกต์สายพันธุ์ / Rank Effect — ตัวเลขขึ้นกับ "แรง" ไม่ใช่เลเวล ✅ ตอบแล้ว

**ชื่อเรียกสองภาษาไม่ตรงกัน:** ไทยเขียน "เอฟเฟกต์สายพันธุ์" แต่อังกฤษเขียน
**"Rank Effect"** — และอังกฤษตรงกับกลไกจริงมากกว่า เพราะตัวเลขมาจาก**แรง (rank)**
ไม่ได้มาจากสายพันธุ์ ฟิลด์ในโครงข้อมูลจึงใช้คำว่า `effectsRank` / `monsterRank`
ตามอังกฤษ ส่วนป้ายบนหน้าเว็บใช้คำของแต่ละภาษาตามที่เกมเขียน (ดู `src/i18n/`)

มอนสเตอร์ลิงมี "เอฟเฟกต์สายพันธุ์" ผูกกับสายพันธุ์ (ต่างจาก "ลักษณะเฉพาะ" ที่สุ่ม
รายตัว จึงไม่เก็บ) แต่ตัวเลขไม่กลม เช่น 5.78% / 8.67% / 11.55% / 6.57%

**คำตอบ (ยืนยันจากผู้เล่น 2026-09-12):** ตัวเลขขึ้นกับ **"แรง" ของมอนตัวนั้น**
แรงมี 5 ขั้น และ **แรงกับเลเวลเป็นคนละเรื่องกัน**

> เทา → เขียว → ฟ้า → ม่วง → **ทอง (สูงสุด)**

> **แรงเดียวกัน ได้ค่าเท่ากันทุกเลเวล**

เพราะเลเวลไม่เกี่ยว จึง**ไม่เก็บเลเวลไว้ข้างตัวเลข** — ถ้าเก็บ คนอ่านจะเข้าใจผิดว่า
ต้องปั้นถึงเลเวลนั้นก่อนถึงได้ค่านี้ ทั้งที่จริงได้ตั้งแต่เลเวล 1

**กติกาของโปรเจกต์: เก็บตัวเลขเฉพาะจากมอนสีทอง** เพราะคนมาดูเว็บเพื่อจะบิ้ว
ไม่มีใครเอาตัวแรงต่ำมาใช้ ค่าที่แสดงจึงเป็น "เพดานของสายพันธุ์นี้"

โครงข้อมูลที่ออกมา:

| | |
|---|---|
| `monsterling.effectsRank` | แรงของมอนที่อ่านตัวเลขมา (คำศัพท์ `monsterRank`) |
| บังคับเมื่อไหร่ | เมื่อ `speciesEffects` มี `value` เท่านั้น |
| ทำไมไม่บังคับตลอด | **รูปแบบ**เอฟเฟกต์ (กระตุ้นด้วยอะไร ให้ผลอะไร) เป็นของสายพันธุ์ ไม่ขึ้นกับแรง — เก็บได้เลยแม้ยังไม่รู้ตัวเลข |
| `validate:data` | เตือนถ้าแรงไม่ใช่ `gold` และเตือนถ้าเอฟเฟกต์ยังไม่มีตัวเลข |

หน้าเว็บต้องกำกับว่าเป็น **"ค่าสูงสุด · แรงสีทอง"** ไม่ใช่ค่าที่ทุกตัวจะได้

**หลักฐานว่าเลเวลไม่เกี่ยวจริง:** ก็อบลิน ร้อยตรี เป็นมอน**แรงสีทองที่ยังเลเวล 1**
(6.57%) เก็บตัวเลขได้ตามปกติ — ไม่ต้องปั้นเลเวลก่อนถึงจะอ่านค่าเพดานได้

**เลขซ้ำข้ามสายพันธุ์ ไม่ใช่ความผิดพลาด:** มอนหลายตัวขึ้นเลขเดียวกันเป๊ะ
(6.25% สี่ตัว, 11.55% หลายตัว, 6.57% สองตัว) ทั้งที่คนละสายพันธุ์

ตอนแรกตีความว่าเป็นสัญญาณว่าอ่านมาจากมอนคนละแรง จึงถือตัวเลขไว้ไม่เก็บ
**ผู้เล่นยืนยันแล้ว (2026-09-12) ว่าตัวเลขไม่ได้ตรงกันทุกตัวอยู่แล้ว และให้เชื่อตามรูป**
จึงเก็บตามที่จอแสดงทั้งหมด

เหตุผลที่ฟังขึ้น: ตัวเลขมาจากแรง ไม่ใช่สายพันธุ์ มอนคนละสายพันธุ์ที่แรงเท่ากัน
จึงได้เลขเท่ากันเป็นเรื่องปกติ — เหมือน 11.55% ที่โผล่ซ้ำในมอนแรงสีทองหลายตัว

### 13.9.2 ตัวเลขเป็น "ฐาน" กับ "ฐาน x 1.05" ไม่ใช่เลขสุ่ม

ไล่เก็บมาหลายวันแล้วเห็นคู่ 6.25 / 6.57 ซ้ำ ๆ จนนึกว่า 6.57 เป็นเลขเฉพาะตัว
พอข้อมูลมากพอ (2026-09-14) ตัวเลขทั้งหมดในไฟล์เข้ารูปเดียวกันหมด:

**ขั้นบน = ฐาน x 1.05 ปัดขึ้นสองตำแหน่ง**

| ฐาน | x1.05 ตรง ๆ | ขั้นบนที่เกมแสดง |
|---|---|---|
| 2.4 | 2.520 | 2.52 |
| 4 | 4.20 | 4.2 |
| 4.69 | 4.9245 | **4.93** |
| 6.25 | 6.5625 | **6.57** |
| 8 | 8.40 | 8.4 |
| 8.25 | 8.6625 | **8.67** |
| 11 | 11.55 | 11.55 |

สามแถวที่ตัวหนาคือแถวที่ชี้ขาดว่าเกม **ปัดขึ้น** ไม่ใช่ปัดปกติ
ถ้าปัดปกติจะได้ 4.92 / 6.56 / 8.66 ซึ่งไม่มีตัวไหนในเกมแสดงเลย
ทั้งเจ็ดแถวเข้ากับการปัดขึ้นพร้อมกันหมด ไม่มีข้อยกเว้น

ผลที่ตามมาต่อการอ่านข้อมูล:

- "คู่ 6.25/6.57" ไม่ใช่ปรากฏการณ์ของตัวเอง เป็นแค่ฐานหนึ่งกับขั้นบนของมัน
  ฐานอื่นก็มีคู่ของตัวเองครบ (8/8.4, 11/11.55, 8.25/8.67, 4.69/4.93, 2.4/2.52, 4/4.2)
- **เลขเท่ากันไม่ได้แปลว่าเป็นคู่กัน** หุ่นฟางพุ่มไม้ (99) กับหุ่นฟางดำ (121)
  ทำงานเหมือนกันเป๊ะ แต่ 6.57 กับ 8 อยู่คนละฐาน จึงไม่ใช่คู่
- **5.5 เจอแล้ว (2026-09-15)** ทากรัก (field 18) ขึ้น 5.5% ซึ่งเป็นฐานของ 5.78
  ที่ทำนายไว้ตรงนี้ตั้งแต่ยังไม่เห็นตัวจริง — เป็นครั้งแรกที่กฎนี้ทำนายค่าที่
  ยังไม่เคยเจอแล้วเจอจริงทีหลัง
  ต่อมาในวันเดียวกัน ต้นสนผู้เฒ่าคิม (field 104) ขึ้น 5.5% เหมือนกัน และเป็น
  **คู่ที่อยู่ติดกัน**กับต้นสนผู้เฒ่าพัค (105) ที่ได้ 5.78 โดยเอฟเฟกต์เหมือนกันทุกช่อง
  (พลังโจมตีของสกิลสับเปลี่ยน) — จากค่าที่ทำนายไว้ กลายเป็นคู่ที่เห็นครบทั้งสองฝั่ง
- ฐานที่ยังไม่เจอขั้นบน: 3.13 / 3.47 / 14 (ฐาน 6 ได้ขั้นบน 6.3 แล้วจากบูกิ ไม้ยักษ์ field 161)

**ยังไม่ใส่ลงข้อมูล** — นี่เป็นข้อสังเกตจากเลขที่เก็บมา ไม่ใช่สิ่งที่เกมเขียนบอก
ห้ามใช้เติมค่าที่ยังไม่ได้อ่านจากจอ ค่าที่ไม่ได้อ่านยังต้องเป็น `null` เหมือนเดิม

### 13.9.3 เซ็ตอุปกรณ์ทองแรงกว่าม่วง แต่ตัวคูณไม่คงที่ ⚠️

**เคยเขียนผิดไว้ตรงนี้** ตอนเห็นเซ็ตทองสองเซ็ตแรก (2026-09-15) เขียนว่า
"ทอง = ม่วง คูณสอง" เพราะสองคู่แรกคูณสองพอดีทั้งคู่
วันต่อมาเจอคู่ที่สามแล้วไม่ใช่ จึงแก้หัวข้อนี้ทั้งอัน

| คู่ | ม่วง | ทอง | ตัวคูณ |
|---|---|---|---|
| Fire RES ลด (Tag-out, 5 วิ) | Mountain Peak Majesty [2] **3%** | Gourmand's Grand Banquet [2] **6%** | **x2** |
| ดาเมจธาตุ ใส่ศัตรูติดสถานะธาตุ | Mountain Peak Majesty [4] **5%** | Arbiter [4] **10%** | **x2** |
| ดาเมจธาตุน้ำแข็ง (โจมตีพื้นฐาน) | Green Nightmare [2] **3% นาน 2 วิ** | Forest Tyrant [2] **7.5% นาน 3 วิ** | **x2.5** |

คู่ที่สามหักกฎสองอย่างพร้อมกัน — ตัวเลขเป็น 2.5 เท่า ไม่ใช่ 2
และ**ระยะเวลาก็เปลี่ยน** จาก 2 เป็น 3 วินาที ทั้งที่คู่แรกระยะเวลาเท่ากันทั้งสองระดับ

มีอีกสองจุดที่เลข 3 -> 7.5 โผล่ซ้ำ แต่**ไม่นับเป็นคู่เต็ม** เพราะ stat ไม่ตรงกัน:

- Ice Heart (ม่วง) "Lightning attack Stagger DMG **+3%**" กับ
  Devourer of the Abyss (ทอง) "Ice Attack Neutralization DMG **+7.5%**"
- Frenzied White Wolf [2] (ม่วง) "All teammates' **DEF +3%** for 5s upon using a Support Skill" กับ
  Sirius [2] (ทอง) "All teammates' **Earth DMG +7.5%** for 5s upon using a Support Skill"
  (2026-09-19) — โครงประโยค**ตรงกันทุกคำ**ที่ไม่ใช่ตัว stat กับตัวเลข
  ทั้งทริกเกอร์ ระยะเวลา และเป้าหมาย และทั้งสองเซ็ตยังเป็นตระกูลหมาป่าขาว
  ชื่อชิ้นใช้แบบเดียวกันด้วย (Frenzied Wolf's Restraints / Ascendant White Wolf's Restraints)
- Stone Heart [2] (ม่วง) "**DEF +3%**" กับ Ancient Stone [2] (ทอง)
  "**Wind Attack Neutralization DMG +7.5%**" (2026-09-19) — สองชิ้นเท่ากัน
  ช่องเดียวกัน (หมวก+รองเท้า) ชื่อแบบเดียวกัน (Stone Mask/Sandals กับ Ancient Stone Mask/Sandals)
  ไม่มีทริกเกอร์ไม่มีระยะเวลาเหมือนกันทั้งคู่ — คนละ stat อีกเช่นกัน

**เลข 3 -> 7.5 โผล่มาสี่ครั้งแล้ว บน stat คนละอันทุกครั้ง** (พลังป้องกัน · Stagger DMG ·
ดาเมจหมดฤทธิ์ · ดาเมจธาตุน้ำแข็ง) ซึ่งชวนให้คิดว่าตัวเลขผูกกับ "ระดับของเซ็ต" มากกว่าผูกกับ stat
**แต่ห้ามสรุปเป็นกฎ** เพราะเซ็ตทองที่อ่านแล้วพิมพ์เลขอื่นก็มี — Abyss [2] **10%** ·
Mount Tai's Towering Might [2] **5%** · Gourmand's Grand Banquet [2] **6%**
นี่คือข้อสังเกต ไม่ใช่สูตร และข้อห้ามข้างล่างยังใช้เหมือนเดิม

จุดเหล่านี้ซ้ำรอยสิ่งที่มอนสเตอร์ลิงคู่ 65/66 สอนไว้ (§13.9.2):
**"อยู่ตระกูลเดียวกัน + ประโยคเหมือนกัน" ไม่ได้แปลว่า "เอฟเฟกต์เดียวกัน"**
ตัวที่ตัดสินคือ stat ไม่ใช่รูปประโยค

**ชื่อเซ็ตกับผลของเซ็ตเป็นคนละสายกัน** (2026-09-19): Mount Tai's Towering Might (ทอง)
ตั้งชื่อชิ้นตาม Mountain Peak Majesty (ม่วง) ช่องต่อช่อง — Helm/Helmet, **Iron Armor คำเดียวกันเป๊ะ**,
Gloves — แต่โบนัสไม่ตรงกันสักข้อ ส่วนเซ็ตทองที่รับผลของ Mountain Peak Majesty มาจริง
คือ Gourmand's Grand Banquet กับ Arbiter ซึ่งชื่อไม่เหมือนกันเลย
**ห้ามจับคู่ม่วง-ทองจากชื่อ ให้จับจากข้อความโบนัส**

**สรุปเท่าที่รู้ตอนนี้: ทองแรงกว่าม่วงบนเอฟเฟกต์เดียวกัน แต่แรงกว่าเท่าไรยังไม่รู้**
เห็น x2 สองครั้ง x2.5 หนึ่งครั้ง (บวกอีกสามครั้งที่ไม่ใช่คู่เต็ม)
ห้ามใช้เติมค่าของเซ็ตที่ยังไม่ได้อ่าน — ซึ่งเป็นข้อห้ามเดียวกับที่เขียนไว้ตั้งแต่ตอนคิดว่าเป็น x2
ข้อห้ามนั้นคือสิ่งเดียวที่กันไม่ให้ความผิดพลาดนี้กลายเป็นข้อมูลผิดในไฟล์

**บทเรียน:** กฎ x1.05 ของมอนสเตอร์ลิง (§13.9.2) ตรวจกับค่าทั้งหมดในไฟล์ก่อนถึงเขียนลง
ส่วนอันนี้เขียนจากสองคู่แล้วพังตอนเจอคู่ที่สาม — สองคู่ไม่พอจะเรียกว่ากฎ

ของอื่นที่ต่างกันระหว่างสองระดับ และยังไม่มีข้อยกเว้น:

- ทองเป็น **5 ดาว** ม่วงเป็น **4 ดาว**
- วัตถุดิบคราฟต์ของทองต้องใช้อย่างละ **5 ชิ้น** ม่วงใช้อย่างละ **3 ชิ้น**
- ค่าคราฟต์เป็นทอง 4,000 เท่ากันทั้งสองระดับ

### 13.9.1 จอไทยตกรายละเอียดที่จออังกฤษมี ⚠️

Master Lizcout: จอไทยเขียน "เมื่อถูกโจมตี จะเพิ่มพลังโจมตีธาตุดิน 6.57%
(ทำงาน 1 ครั้ง ทุก 20 วินาที)" — **ไม่มีระยะเวลา**
จออังกฤษเขียน "Earth ATK +6.57% **for 10s** upon being hit (Cooldown: 20s)"

แปลว่าข้อมูลที่กรอกจากจอไทยอย่างเดียว **อาจขาดฟิลด์ไปโดยไม่มีอะไรเตือน**
ต่างจากกรณีตัวเลขไม่ตรงกัน (Freeze 2s/5s) ซึ่งอย่างน้อยยังเห็นว่าขัดกัน

ทางปฏิบัติ:

- ถ้าได้จออังกฤษมาด้วย ให้ถือว่าอังกฤษ**ละเอียดกว่า** เมื่อมันมีฟิลด์ที่ไทยไม่มี
- ของที่กรอกจากไทยอย่างเดียวแล้วรูปแบบตรงกับตัวที่ยืนยันอังกฤษแล้ว
  **ห้ามเติมตามกันเอง** ให้ติดธง `fieldsUnverified` รอจออังกฤษของตัวนั้น
  (ทำแบบนี้กับ Lizcout ไปแล้ว)

### 13.10 ชนิดดาเมจอยู่ที่ "ท่า" ไม่ใช่ที่ "ตัวละคร" ⚠️

**กายภาพ = การตีธรรมดา** ไม่ใช่ธาตุที่เจ็ดหรือแปด และ:

- ตัวละครหลายตัว **ตีปกติเป็นกายภาพ แต่สกิลเป็นธาตุ**
- บางตัว **ใช้สกิลแล้วการโจมตีปกติเปลี่ยนเป็นธาตุ**

แปลว่า ชนิดดาเมจ **เปลี่ยนได้ระหว่างสู้** และต่างกันในตัวละครคนเดียว

ผลที่ตามมา:

| | |
|---|---|
| `skills.*.damageType` | แหล่งความจริงของชนิดดาเมจ เก็บรายสกิล |
| `skills.*.changesBasicAttackTo` | สกิลที่เปลี่ยนธาตุของการตีปกติ |
| `character.element` | **ใช้เป็นหมวดหมู่/ตัวกรองเท่านั้น ห้ามเอาไปคิดดาเมจ** |

ถ้าเครื่องคำนวณไปหยิบ `character.element` มาใช้ทุกท่า มันจะคิดได้เปรียบ/เสียเปรียบธาตุ
ผิดทันทีสำหรับตัวที่ตีปกติเป็นกายภาพ — และผิดแบบ**ดูน่าเชื่อ** เพราะตัวเลขออกมาสวย

ตอนต่อ `computeDamage` เข้ากับข้อมูลจริง ต้องรับชนิดดาเมจ**ของท่าที่กำลังคิด**
เป็นพารามิเตอร์ ไม่ใช่ดึงจากตัวละคร

### สรุปสิ่งที่ต้องเคาะก่อนกรอกข้อมูล

1. ยอมรับนโยบาย **ห้ามแก้ id** หรือไม่
2. ค่าสเกลสกิลจะกรอกแบบไหน (แนะนำ LV 1/12/16)
3. เปลี่ยน `source.by` เป็นบังคับหรือไม่ (แนะนำ: ใช่)

ที่เหลือรอได้จนกว่าจะเจอปัญหาจริง
